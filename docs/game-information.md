# ゲーム情報取得の最初の縦切り

[機能仕様](specification.md) の実装順ステップ1のうち、論理サーバーだけで完結する取得処理を実装した段階です。ステップ1全体の完了ではありません。

## 今回使えるもの

ワールドに参加して、次の確認用コマンドを実行します。チートの有効化・OP 権限は不要です。

```text
/potamaid info
```

実行したプレイヤー自身の情報を、チャットに構造化したテキストとして表示します。

| 内容 | 値 |
|---|---|
| プレイヤー | UUID・プロフィール名 |
| 現在地 | ディメンション ID・小数の X/Y/Z 座標 |
| 向き | yaw（水平）・pitch（上下）。Minecraft の角度を度単位でそのまま保持 |
| メインハンド・オフハンド | アイテムのレジストリ ID・個数 |

空の手は `minecraft:air`、個数 `0` になります。アイテムのコンポーネント・NBT・表示名は今回の取得対象に含みません。

他プレイヤーへの一斉通知は行いません。コンソールから実行した場合は、プレイヤーが必要という Minecraft 標準のエラーになります。他のプレイヤーを指定する引数や自動選択はありません。

このコマンドと表示 JSON は、情報取得を確認するためのものです。MCP のツール名・入出力や Bridge のメッセージ形式を確定するものではありません。AI の実行・会話の管理・外部との通信は含みません。

## 実装の境界

- `game/PlayerSnapshot`: UUID・文字列・数値だけの不変な取得結果。Minecraft のプレイヤー・ワールド・`ItemStack` への参照を外へ持ち出しません。
- `game/GameInformationService`: Minecraft に依存する取得処理。NeoForge、MCP、Bridge、チャット表示には依存しません。将来の MCP と添付機能はこの処理を共用できます。
- `server/GameInformationCommands`: NeoForge のコマンド登録と結果表示だけを担当します。

`getPlayerNow(UUID)` はサーバースレッドからだけ呼び出せます。別スレッドから呼ぶと、ゲーム状態を読む前に拒否します。

将来の通信用スレッドからは `getPlayer(UUID, Duration)` を使います。サーバースレッドに処理を渡し、`CompletableFuture<PlayerSnapshot>` を返します。対象のプレイヤーは処理を実行するときに検索するため、その前に切断していれば失敗します。ゲームスレッドでこの Future の完了を待ってはいけません。

- 対象が不在・切断済み: `NoSuchElementException`
- 同期入口のスレッド違反、サーバーが稼働していない: `IllegalStateException`
- 停止済みのサーバーへのディスパッチ拒否: `RejectedExecutionException`
- 指定時間内に完了しない: `TimeoutException` で Future が失敗
- 正でない待ち時間: `IllegalArgumentException`

タイムアウトまたはキャンセル済みのキュー内の要求は、実行時にスキップします。サーバーやワールドを static に保持せず、取得結果もキャッシュしません。将来の MCP 層はサーバーの起動ごとにサービスを生成し、停止時に破棄する必要があります。エラーの MCP 応答への変換と待ち時間の運用設定は、通信層を作る段階で扱います。

## 検証

Windows の PowerShell では次を実行します。Java 21 が必要です。

```powershell
.\gradlew.bat build
.\gradlew.bat runGameTestServer -PgameTests
```

`build` は本体とテストのコンパイルを確認します。GameTest の実行は2つ目のコマンドです。テストコードは `test` ソースセット（`src/test/`）に置き、配布 jar には含めません。`-PgameTests` の指定時だけテストを Mod の実行対象へ加えます。

GameTest は `build/gametest/` の専用ワールドで動き、終了します。通常の `run/` のワールドは使いません。`src/test/resources/data/potamaid/structure/empty.nbt` は、テスト配置用の 1×1×1 の空の構造物です。

7件のテストで次を確認します。

- 位置・向き・ディメンション・両手のアイテム（Mod のアイテムを含む）と、取得後にゲームを変更しても以前の取得結果が変化しないこと
- 空の手の正規化と、切断後のプレイヤーが不在として扱われること
- サーバースレッド以外からの直接読み取りを拒否すること
- 別スレッドから受け付けた要求をサーバースレッドで実行できること
- サーバースレッドがキューを処理できない間もタイムアウトし、後から結果を上書きしないこと
- 0・負の待ち時間を拒否すること
- コマンド登録、非 OP の本人への JSON 表示、コンソールでの対象なしエラー

テストは Minecraft 1.21.1 の `GameTestHelper.makeMockServerPlayerInLevel()` を利用します。このバージョンでは非推奨警告が出ますが、実際のプレイヤーリストへの登録と接続を含めて検証するために使っています。

クライアントの画面表示、日本語での表示、通常の統合サーバーでの操作、実プレイヤーによるマルチプレイ、停止・再起動時の接続ライフサイクルは、この GameTest では検証していません。

## 次に進む前の確認事項

以下は今回決めていません。該当機能へ進むときに作者への確認が必要です。

1. **MCP の具体的なツール一覧と入出力**: 今回の位置・向きと手持ちをどのツールとして公開するか、対象の指定方法、エラーの形式。内部の `PlayerSnapshot` をそのまま通信契約にはしません。
2. **MCP の接続設定**: ポートの決め方、認証、`Origin` 検証、接続情報の伝え方。HTTP ベースという方針は仕様の決定に従い、詳細を独自に決めません。
3. **クライアント情報の取得**: 提供をブロックする設定の粒度・名前、複数人から対象を選ぶ確認方法。見ているブロックの取得・スクリーンショットなど、クライアントへの要求が必要な機能に着手する前に確認します。
4. **Bridge との通信**: WebSocket と JSON を使う方針は決定済みですが、メッセージの種類・形式、接続先・認証などは未決定です。今回の取得処理には依存させていません。

ログ・周囲のエンティティ・ブロックやエンティティの情報、スクリーンショット、添付 UI、MCP サーバー、Bridge は未実装です。旧 `feat/chat-claude` の CLI 子プロセス実行・チャット管理・開発用ディメンションは取り込んでいません。
