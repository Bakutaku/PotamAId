# コミットメッセージ規約

このプロジェクトでは [Conventional Commits](https://www.conventionalcommits.org/ja/v1.0.0/) に従います。
release-please がコミットメッセージを読み取り、次のバージョン番号と CHANGELOG を自動で決めるため、**形式を守ることが必須**です。

## 形式

```
<type>: <説明>

<本文（任意）>

<フッター（任意）>
```

- `<説明>` は日本語で、何をしたかを簡潔に書きます（末尾に句点は付けない）。
- 本文には「なぜ変更したか」を書きます。何を変えたかはコードの差分で分かるため、理由を優先します。

### 例

```
feat: 川の近くに生成される鉱石ブロックを追加
fix: サーバー起動時に設定ファイルが読み込まれない問題を修正
docs: 導入手順に NeoForge のバージョンを追記
```

## type 一覧

| type | 用途 | バージョンへの影響 | CHANGELOG |
|---|---|---|---|
| `feat` | 新機能の追加 | マイナー（0.1.0 → 0.2.0） | 新機能 |
| `fix` | バグ修正 | パッチ（0.1.0 → 0.1.1） | バグ修正 |
| `perf` | パフォーマンス改善 | パッチ | パフォーマンス改善 |
| `revert` | 以前のコミットの取り消し | パッチ | 取り消し |
| `docs` | ドキュメントのみの変更 | なし | 載せない |
| `style` | 動作に影響しない見た目の変更（フォーマット等） | なし | 載せない |
| `refactor` | 動作を変えないコードの整理 | なし | 載せない |
| `test` | テスト（GameTest 等）の追加・修正 | なし | 載せない |
| `build` | Gradle 設定・依存関係の変更 | なし | 載せない |
| `ci` | GitHub Actions の変更 | なし | 載せない |
| `chore` | 上記以外の雑務 | なし | 載せない |

テクスチャ・モデル・翻訳ファイルなどのアセット追加も、プレイヤーから見て新しい要素であれば `feat`、誤りの修正であれば `fix` を使います。

## 破壊的変更

既存のワールドや設定ファイルとの互換性がなくなる変更（アイテム ID の変更・削除、設定項目の名前変更など）は、type の後に `!` を付け、フッターに `BREAKING CHANGE:` で内容を書きます。

```
feat!: 鉱石ブロックの ID を potamaid:ore から potamaid:river_ore に変更

BREAKING CHANGE: 既存ワールドに置かれた旧 ID のブロックは消失する
```

0.x の間は破壊的変更でもマイナーバージョンが上がります（0.1.0 → 0.2.0）。1.0.0 以降はメジャーバージョンが上がります。

## PR タイトルについて

main へは **Squash merge** でマージするため、main に残るコミットメッセージは **PR のタイトル** になります。
そのため、作業ブランチ内の途中コミットは自由な形式で構いませんが、**PR タイトルは必ずこの規約に従ってください。**

PR タイトルの形式は CI（PR Title ワークフロー）でチェックしています。形式が違うとチェックが失敗し、マージできません。タイトルを直すと自動で再チェックされます。
なお、マージ画面でコミットメッセージを書き換えた場合、その内容はチェックされません。

1つの PR に複数の種類の変更（例: 新機能とバグ修正）を混ぜず、PR を分けることを推奨します。
